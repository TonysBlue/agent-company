## 1. 执行摘要

声检是一款面向中国个人内容创作者的音频校对与返工工具。用户上传自己有权处理的原稿和配音音频，系统自动对齐文本与声音，标出漏读、重复、疑似错读、数字与术语不一致、异常静音、异常音量等问题，并让用户在时间轴上试听、确认和导出返工清单。

首阶段不做通用配音平台，也不承诺自动判断声音是否“好听”。产品解决的是一个可检查、可重复、可量化的问题：创作者在发布前需要完整听一遍音频并手工记录问题，长音频的检查和返工耗时高，而且容易漏掉错误。

商业模式采用预付费处理包起步，待重复使用得到验证后再测试订阅：

- 免费体验：首个项目最多 10 分钟或 8,000 字符，只展示完整检查结果，可导出部分结果；
- 项目包：拟议价 29 元，包含 120 分钟音频检查额度，购买后 60 天有效；
- 创作者月卡：拟议价 49 元，包含 300 分钟；仅在重复使用成立后测试；
- 超额包：拟议价 19 元/120 分钟；不设置无限量方案。

以上均为待验证价格，不是已批准的公开报价。首个商业目标不是收入规模，而是证明三件事：真实创作者愿意上传真实项目、产品能显著减少检查时间、至少部分用户愿意再次付费。

项目采用四道门推进：问题验证、离线原型、付费封闭测试、受控 Beta。任何一门未达到预先设定的阈值，就停止、缩小或调整方向。

## 2. 用户与问题

### 2.1 初始目标用户

只服务同时满足以下条件的个人创作者：

- 每月至少制作两次 10 分钟以上的中文旁白、播客、课程、有声故事或知识音频；
- 已经使用配音、剪辑、字幕或语音工具，并承担时间或软件成本；
- 对发布错误敏感，愿意在发布前检查；
- 拥有原稿及音频的合法处理权；
- 可以自行判断系统标记的问题是否需要修改。

初期优先顺序：

1. 知识口播与教程创作者；
2. 个人播客和音频栏目作者；
3. 原创故事及有声内容创作者；
4. 小型自媒体工作室中的个人操作者。

暂不服务需要医学、法律或金融内容正确性背书的场景，也不处理未经授权的影视解说稿、声音克隆或第三方私密录音。

### 2.2 核心任务

用户需要在发布前回答：

- 是否有句子漏读、重复或读成了别的内容？
- 人名、术语、金额、日期和序号是否前后一致？
- 哪些位置存在过长静音、截断、音量异常或文件缺失？
- 需要返工的片段分别在哪里？
- 修改后是否修复了问题，又没有产生新的差异？

当前替代方案包括完整通听、边听边记录、在剪辑软件中看波形、依赖配音平台试听，以及让他人复听。这些替代方案普遍可用，因此声检必须用真实项目证明其节省时间的幅度，不能只证明技术可以运行。

### 2.3 价值主张

产品承诺采用可验证表述：

> 上传原稿和音频，先检查最值得重听的位置，再完成发布前确认。

不使用“零错误”“完全自动审音”“保证发布质量”等无法兑现的表述。系统给出的是带证据的疑似问题和定位，不替用户做最终判断。

## 3. 市场与竞争判断

公开证据表明，中国创作者会为配音生产软件付费。魔音工坊招股文件披露，其 2023 年付费用户约 40.4 万，定义为当年发生订阅、续订或其他购买的用户；中国区 App Store 当前列有 60 元月会员和 348 元年会员。该证据证明配音工作流存在付费行为，不证明用户已经愿意单独为校对工具付费。

成熟配音工具已经提供多发音人、多音字、停顿、局部变速、字幕下载和自动打轴。声检不能以这些现成功能作为差异化。其唯一可接受的初始切口是跨平台检查：无论音频由真人录制、某个配音平台还是剪辑软件生成，都能对照用户原稿定位风险并生成返工清单。

竞争风险很高。出门问问 2025 年年报显示，包含企业业务和 AIGC 在内的 AI 软件解决方案收入由 2024 年约 2.381 亿元降至 2025 年约 1.488 亿元，管理层提到竞争加剧以及控制 AIGC 获客投入。这说明行业有付费需求，同时存在产品同质化和获客压力。

### 3.1 直接与间接竞品

| 类型 | 用户现有选择 | 声检需要证明的差异 |
| --- | --- | --- |
| 配音平台 | 合成、试听、发音调节、字幕 | 跨平台原稿对照、批量问题定位、修改前后复检 |
| 剪辑软件 | 波形、时间轴、字幕、手工调整 | 自动把文本差异和音频异常映射到具体时间点 |
| 语音转写工具 | 音频转文字 | 原稿与转写对齐、风险排序、证据试听和返工闭环 |
| 人工通听 | 判断能力强、无需学习新工具 | 在可接受的误报下显著减少完整通听时间 |

### 3.2 可建立的产品资产

底层语音识别模型本身不是护城河。可积累的资产是：

- 创作者真实确认过的错误类型与修正结果；
- 针对中文数字、人名、专有名词和口播结构的对齐规则；
- 用户自己的术语词典和项目历史；
- 修改前后复检工作流；
- 按内容类型校准的风险排序和置信度；
- 可靠、快速、尊重隐私的文件处理体验。

任何用户数据训练或跨用户利用都必须另行取得明确授权；默认不把用户内容用于训练。

## 4. 产品范围

### 4.1 MVP 必须完成

1. 上传 TXT、DOCX 或粘贴原稿；上传 MP3、M4A、WAV 音频。
2. 校验文件格式、大小、时长和音频可读性。
3. 生成带时间戳的转写结果。
4. 将转写与原稿分段对齐。
5. 标记：
   - 疑似漏读；
   - 疑似重复；
   - 疑似替换或错读；
   - 数字、日期、金额、序号差异；
   - 用户词典中的术语差异；
   - 过长静音；
   - 峰值过高、过低或明显音量跳变；
   - 音频疑似截断。
6. 每项问题显示原稿、识别文本、时间点、置信度和一键试听片段。
7. 用户可以确认、忽略、修改备注，并保留原因。
8. 导出 CSV、JSON 和可打印的检查报告。
9. 修改后的音频可以再次上传，比较问题是否消失。
10. 自动删除到期文件，并允许用户立即删除项目。

### 4.2 MVP 明确不做

- 不生成完整配音，不克隆用户或第三方声音；
- 不自动修改或覆盖用户原始文件；
- 不承诺判断情绪、审美、自然度或事实真伪；
- 不接入公开发布平台，不替用户发布内容；
- 不支持多人协作、企业权限、开放 API 或移动原生 App；
- 不用用户内容训练模型；
- 不提供无限额度；
- 不处理实时通话或监控录音。

### 4.3 MVP 之后的候选能力

只有真实数据证明需求后，按顺序评估：

1. 一键生成返工片段边界和配音指令；
2. 对接一种合法可商用的语音服务进行局部重配；
3. 自动拼接经用户确认的新片段，并保留原文件；
4. 批量项目和栏目级术语库；
5. 剪辑软件可导入的标记文件；
6. 创作者月卡与团队版。

## 5. 用户体验

主流程控制在六步：

1. 新建项目并确认自己有权处理内容；
2. 上传原稿和音频；
3. 系统预检，明确预计耗时和计费额度；
4. 生成按风险排序的检查列表；
5. 用户逐项试听、确认或忽略；
6. 导出返工清单，修改后复检。

结果页首先显示：检查了多少分钟、建议重听多少分钟、发现多少个高置信问题、哪些内容因识别不确定仍建议完整确认。失败时必须解释原因并自动退还未完成任务消耗的额度。

## 6. 技术实施方案

### 6.0 仓库与资产边界

声检采用与 PixWeave 相同的独立产品仓模式。建议仓库为 `TonysBlue/VoiceProof`，本机工作副本为 `/home/tony/VoiceProof`。它是 Agent Company 管理的产品资产，但不是 `agent-company` 仓库目录中的 Git 子仓，也不使用 Git submodule。

边界如下：

- `agent-company`：战略、阶段、任务、审批、RACI、经营指标、跨产品决策和审计；
- `VoiceProof`：产品源代码、测试、技术与产品文档、示例、部署模板和版本发布记录；
- `/home/tony/product-data/voiceproof`：运行数据、用户上传文件、中间音频、转写结果、账单明细和运行日志；该目录不进入 Git；
- `/home/tony/agent-workspaces/<role>/task-<id>-VoiceProof`：任务级执行工作区；
- `agent-company/evidence/`：只保留不含用户正文和敏感信息的验证摘要、哈希、版本、指标和审批证据，不复制产品源文件或真实用户内容。

Agent Company 通过仓库 URL、默认分支、提交哈希、发布版本和证据路径管理产品，不把产品代码嵌入控制平面。产品仓可以独立测试、发布、归档、回滚或转让；公司系统也不会因产品依赖而扩大部署和安全范围。

不采用 Git submodule 的原因：它会把产品提交指针混入控制平面变更，增加代理工作区、权限、CI、发布和恢复的耦合。只有将来确实存在必须一起构建、原子发布的共享代码时，才另行评估版本化包或专门共享仓库；当前没有这个需求。

### 6.1 产品形态

先做响应式 Web 应用。它能用链接快速招募测试者，免去首轮 App 审核和多端开发。付费 Beta 前完成国内网站与支付所需的主体、备案和服务配置。

### 6.2 系统组成

| 模块 | 职责 |
| --- | --- |
| Web 前端 | 上传、任务状态、时间轴试听、问题确认、报告导出 |
| API 服务 | 账号、项目、额度、任务编排、权限和删除请求 |
| 对象存储 | 加密保存原稿、音频、中间结果和导出文件 |
| 异步工作队列 | 转写、对齐、音频分析、报告生成、重试和超时 |
| 语音识别适配层 | 支持替换供应商，记录模型、版本、成本和请求结果 |
| 文本对齐引擎 | 分句、规范化、动态对齐、差异分类和置信度 |
| 音频检查引擎 | 静音、响度、峰值、时长和截断检测 |
| 计费与额度 | 预估、冻结、结算、失败返还、对账和退款证据 |
| 运营后台 | 匿名指标、失败原因、工单、成本和删除状态 |

### 6.3 核心处理流程

1. 浏览器上传前完成扩展名、大小和时长初检。
2. 服务端以内容哈希创建不可重复提交的项目任务。
3. 原稿规范化时保留原始字符位置，不改变原文件。
4. 音频转写返回分句、词级或句级时间戳及置信度。
5. 对齐引擎使用分段候选、编辑距离和时间连续性生成匹配。
6. 规则引擎识别数字、金额、日期、英文缩写和用户词典项。
7. 音频引擎独立计算静音与响度指标。
8. 风险排序合并文本和音频证据，避免把低置信识别直接当作错误。
9. 用户确认结果写入独立事件记录，用于项目历史和评估；默认不用于训练。
10. 到期任务触发文件删除并记录删除证明。

### 6.4 供应商与成本控制

采用可替换的国内合规语音识别服务，第一版同时评测至少两家。供应商选择标准：中文长音频准确性、词级时间戳、热词支持、数据处理条款、境内服务、删除机制、稳定性和价格。

公开参考价格显示，大模型录音文件识别可低至约 0.039 元/分钟；实际预算按 0.10 元/分钟计入识别、重试和波动缓冲。120 分钟项目包按这一保守假设的语音处理成本约 12 元，另加存储、带宽、模型、支付和退款准备金。上线前必须以真实账单替换所有估计。

每个任务在执行前冻结额度，成功后结算，系统错误自动返还。设置单项目时长、文件大小、并发和每日成本上限，避免滥用与成本失控。

### 6.5 安全与隐私

- 传输使用 TLS，文件采用服务端加密，存储路径不可预测；
- 原始内容与运营指标分离，后台默认看不到文本和音频正文；
- 日志不记录原稿、转写正文、文件 URL、支付资料或认证凭据；
- 默认保存 7 天，用户可选择 24 小时或立即删除；
- 删除覆盖原文件、中间文件、缓存和可控备份生命周期；
- 下载链接短时有效；
- 每个项目校验所有权，防止跨账户访问；
- 供应商和子处理方在隐私政策中透明列示；
- 用户内容不进入 Git、Agent 上下文或普通内部文档；
- 真实内容问题排查使用用户明确授权的短片段和工单流程。

## 7. 质量评估

### 7.1 主要评估问题

对真实目标用户而言，使用声检后完成一次发布前检查的总时间，是否显著少于完整人工通听，同时不增加不可接受的漏检和返工？

### 7.2 指标定义

| 指标 | 定义 | 阶段目标 |
| --- | --- | ---: |
| 工作流完成率 | 上传成功并完成结果确认的项目 / 合格开始项目 | ≥80% |
| 高风险精确率 | 用户确认确需处理的高风险项 / 展示的高风险项 | ≥70% |
| 严重问题召回率 | 金标准严重问题中被系统标出的比例 | ≥90% |
| 检查时间节省 | 相对完整人工通听的中位时间下降 | ≥50% |
| 人工介入率 | 需要公司人员查看内容或手工修复的项目比例 | ≤5% |
| 处理成功率 | 无人工干预完成的合格任务比例 | ≥95% |
| 首次付费率 | 完成免费真实项目用户中购买者比例 | ≥10% |
| 60 日重复付费率 | 首次付费用户中再次购买者比例 | ≥20% |
| 退款率 | 退款订单 / 付费订单 | ≤8% |
| 单位贡献 | 收入减支付、推理、存储、退款和可归因获客成本 | >0 |

“严重问题”仅包括漏读整句、重复整句、关键数字或术语错误、明显截断等可清楚定义的问题。情绪或声音自然度不计入自动质量承诺。

### 7.3 离线测试集

建立 60 个有权使用的样本：

- 20 个真人口播；
- 20 个主流语音服务生成音频；
- 20 个混合场景，包含背景音乐、轻微噪声或长稿。

每类包含自然正确样本和人工植入的漏读、重复、替换、数字、术语、静音、音量及截断问题。至少两人独立标注隐藏测试集，争议由独立质量角色裁决。开发集与隐藏测试集分离，所有失败必须保留匿名化原因和版本信息。

## 8. 商业模式与单位经济

### 8.1 收费实验

依次测试，不同时开放过多选择：

1. 第一轮：29 元/120 分钟、60 天有效；
2. 第二轮：19 元/60 分钟与 39 元/180 分钟，比较购买和使用完成情况；
3. 只有 60 日重复使用达到门槛后，测试 49 元/月、300 分钟；
4. 不采用自动续费作为首轮方案；以后启用时必须在购买前及扣费前显著提醒，并提供直接取消入口。

### 8.2 单位经济模型

每个订单记录：

`贡献毛利 = 实收 - 支付费 - 语音识别 - 文本模型 - 存储与带宽 - 退款损失 - 可归因获客成本 - 人工支持成本`

以 29 元/120 分钟项目包做规划示例：

| 项目 | 保守假设 |
| --- | ---: |
| 实收 | 29.00 元 |
| 语音及模型处理 | 12.00 元 |
| 存储、带宽与支付 | 2.00 元 |
| 退款与失败准备 | 2.00 元 |
| 获客成本上限 | 7.00 元 |
| 目标贡献 | 6.00 元 |

这是决策模型，不是已测成本或利润承诺。实际账单和订单数据优先。一旦连续两轮付费实验的订单贡献为负，停止付费获客并调整价格、额度或产品。

## 9. 获客与运营

### 9.1 首批渠道

优先接触已经公开讨论配音返工和音频检查的创作者：小红书、B 站、知乎、播客创作者社群和音频工具相关内容下的公开场景。外部招募、发布及联系用户须先获得 Chairman 对具体文案、渠道、样本量和数据处理方式的批准。

首批内容只展示真实、可复现的工作流：

- 一段 20 分钟音频中人为加入 6 个错误；
- 完整通听与声检辅助检查分别耗时多少；
- 哪些问题找到，哪些漏掉，误报多少；
- 用户如何确认和导出返工清单。

不购买泛流量，不用“AI 创业”“一键无错”等泛化宣传。按内容触达、开始真实项目、完成项目、付费和复购逐层计算转化。

### 9.2 自动化运营

- 自助演示项目和文件格式预检；
- 任务失败自动分类、重试、返还额度和通知；
- 使用完成后只询问与该项目有关的结构化反馈；
- 帮助中心根据真实失败类型生成并经抽样审核后发布；
- 退款根据未使用额度、系统失败和重复支付执行明确规则；
- 异常成本、删除失败、跨账户访问和大量投诉自动停单并升级；
- 每周自动汇总漏斗、成本、失败和确认标签，CEO 根据证据决定下一迭代。

运营自动化不包括自动公开发帖、冒充用户互动、隐瞒 AI 使用、自动处理法律争议或拒绝合理退款。

### 9.3 客服边界

产品内只承诺文件处理、问题定位、额度和删除支持。对于创作建议、内容事实、版权归属和发布决策，提供边界说明，不开展人工代制作。每 100 个完成项目人工处理不应超过 5 个；超过门槛说明产品或帮助系统尚不能自动运营。

## 10. 分阶段实施计划

### 阶段 0：问题验证与技术探针（第 1–2 周）

目标：确认问题存在，并判断自动检查是否可能产生足够价值。

产品工作：

- 创建独立 `VoiceProof` 产品仓及基础质量检查，不将其作为 `agent-company` 子模块；
- 用内部或明确授权样本比较两家语音识别服务；
- 完成原稿与转写对齐、数字与术语检查、静音检测的命令行探针；
- 建立 20 个开发样本和 20 个隐藏样本；
- 记录准确性、处理时间和真实成本。

商业工作：

- 准备三分钟可交互演示和一页价值说明；
- 获批后招募 15 位符合条件的创作者做问题访谈与任务观察；
- 访谈不问“你喜不喜欢”，要求用户展示上一次项目的检查方式、耗时和付费工具；
- 至少 8 人提供可验证的近期真实工作流，至少 5 人愿意提交测试项目，才进入下一阶段。

交付物：问题证据报告、竞品流程对比、技术探针、成本基线、隐私数据流图。

### 阶段 1：本地 MVP（第 3–5 周）

目标：让内部人员和授权测试者完成端到端流程。

- 实现上传、异步任务、对齐、问题列表、试听和报告导出；
- 实现任务幂等、失败重试、额度模拟和删除；
- 在 60 个离线样本上完成基线评估；
- 使用 5–8 个真实授权项目做观察测试；
- 处理成功率达到 90%，高风险精确率达到 65%，严重问题召回达到 85%，才准备封闭测试。

### 阶段 2：免费封闭测试（第 6–7 周）

目标：验证真实用户能否自助完成，以及是否节省时间。

- 上限 30 位测试者、60 个项目；
- 测试者先按原方法检查一个项目，再用声检查一个可比项目；
- 记录总时间、误报、漏检、人工介入和满意原因；
- 至少 24 人完成完整流程，中位检查时间下降 50%，人工介入不超过 10%，才申请付费测试。

### 阶段 3：付费封闭测试（第 8–10 周）

目标：验证真实付款与单位经济。

- 上限 100 位用户和 200 个付费项目；
- 首轮只提供 29 元项目包，不自动续费；
- 免费真实项目完成者中至少 10% 付款；
- 至少 20 个真实付费订单；
- 成功项目人工介入不超过 5%；
- 订单贡献在纳入获客与退款后为正；
- 没有严重数据、删除、计费或跨账户事故。

### 阶段 4：受控 Beta（第 11–13 周）

目标：验证重复使用和可持续获客。

- 扩展至 300 位注册用户，维持明确容量上限；
- 比较内容案例、搜索内容和创作者推荐三种获客方式；
- 测试第二档项目包；
- 观察首批付费用户的 60 日重复购买；
- 只有重复购买达到 20%、单位贡献为正、退款低于 8%，才进入月卡实验。

### 阶段 5：订阅与扩展决策（第 14 周后）

三种决策：

- 继续：重复付费与贡献成立，测试 49 元创作者月卡；
- 收窄：某一内容类型显著优于其他类型，聚焦该场景；
- 停止：用户不付费、时间节省不足、人工介入过高或获客后持续亏损。

## 13. 合规与阶段审批

在公开或收费前完成：

- 经营主体、网站/应用备案及支付能力；
- 用户协议、隐私政策、第三方处理方清单和删除规则；
- 明示用户须拥有原稿和音频处理权；
- 个人信息最小化、访问控制、数据留存和用户删除机制；
- 未成年人、违法内容、侵权内容和滥用处理规则；
- 明确 AI/自动处理的范围，不夸大检查能力；
- 价格、额度、有效期、退款和失败返还显著展示；
- 若未来生成或导出 AI 合成内容，另行落实适用的生成合成内容标识要求。

以下动作分别需要 Chairman 的具体批准：真实用户招募、公开发布、付费定价、支付开通、生产部署、真实用户文件处理、营销费用和任何合同或法律承诺。批准材料应包含范围、文案、期限、预算、数据类型、供应商和回滚方式。

## 14. 主要风险及应对

| 风险 | 早期信号 | 应对 |
| --- | --- | --- |
| 用户不认为校对值得单独付费 | 愿试用但拒绝 29 元 | 停止独立产品，评估插件或配音平台合作，不补贴虚假需求 |
| 误报过多 | 用户重听时间没有下降 | 收紧高风险阈值，低置信项折叠；按内容类型校准 |
| 漏掉关键错误 | 严重问题召回低于 90% | 明示剩余风险，改进对齐；达不到门槛不公开上线 |
| ASR 供应商成本或质量波动 | 同一版本成本或失败率显著变化 | 双供应商适配、成本上限、版本锁定和回归测试 |
| 内容隐私事故 | 未授权正文出现在日志或支持系统 | 最小化日志、加密、访问审计、自动停单和事件响应 |
| 获客成本超过贡献 | 连续两轮 CAC 超过可承受上限 | 停止投放，聚焦自然案例和推荐；重新评估产品 |
| 成熟平台快速复制 | 竞品增加同类原稿对照 | 依靠跨平台、用户确认数据和返工闭环；仍无优势则退出 |
| 运营需要大量人工 | 每 100 项目超过 5 个需人工 | 修复自助流程或停止扩量，不用人工掩盖产品缺陷 |

## 15. 停止或转向条件

出现任一条件时，CEO 必须暂停扩量并提出停止或转向建议：

- 15 位合格访谈对象中，少于 8 位能证明近期存在该工作流；
- 少于 5 位愿意用真实项目测试；
- 离线严重问题召回无法达到 85%；
- 封闭测试中位时间节省低于 30%；
- 付费实验完成后少于 10 个真实付款，且原因主要是价值不足；
- 两轮价格实验后首次付费率仍低于 5%；
- 60 日重复付费低于 10%；
- 人工介入率持续高于 10%；
- 连续两轮真实订单贡献为负；
- 出现无法有效控制的数据、版权、计费或合规风险。

达到停止条件不以增加功能、降低价格或延长实验自动豁免。任何继续投入都要有新的证据和明确的新假设。
